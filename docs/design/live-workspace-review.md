# 持续评分工作台：原型与实现复核

> 2026-09-22 补充复核：以下原型是视觉方向稿。实现以 1536×1024、DPR 1 复核，但原型使用静态演示数值，不能宣称与 fixture “同数据”或像素级 1:1。Copy gate: **passed**。390px 使用独立 Chromium；200% 使用普通 Chrome 原生缩放并在验收后恢复 100%。

## Copy gate（实现前）

| 用户事实 | 承载位置 | 生命周期 | 文案/动作 |
| --- | --- | --- | --- |
| 事件仅在接收并持久化后才可观察 | 空状态、接收量 | 首次进入到第一条 ACK | “等待第一批生产事件” / 说明不会触发业务请求 |
| 覆盖率不等于业务正确率 | KPI 标题旁提示 | 每次查看窗口 | “评分覆盖率” + 信息提示 |
| 暂停不丢事件 | 顶部状态条与主操作 | 已暂停期间 | “评分已暂停，接收与持久化仍在继续” / 恢复评分 |
| 迟到证据在窗口结束后仍可修订 | 窗口状态与 Drawer | 当前快照存在期间 | “窗口已结束，迟到证据仍可修订” / “查看最新” |
| 导出的快照可以带走 | Drawer 与窗口表 | 窗口可查询时 | “导出窗口” |
| 原始上游响应不可在页面泄漏 | 局部错误区 | 请求失败时 | 仅显示稳定中文错误码映射与重试 |

## 实现后检查项

- 1536×1024、DPR 1 桌面和 Drawer 已用真实构建、真实 API 与固定数据截图；390×844 单独验证布局重排。
- 200% 等效布局最初暴露侧栏挤压和页面横向溢出；紧凑断点由 760px 调整为 820px。补充验收在普通 Chrome 原生 `Zoom: 200%` 下确认顶部导航、计划选择、范围、刷新/暂停和 KPI 可达，随后恢复 `Zoom: 100%`。
- 页面真实验证了暂停提示、积压增长与恢复、旧 Drawer 保持 revision 47 并提示 revision 50、局部安全错误、键盘顺序、Escape 关闭及 reduced-motion。
- 证据位于 `output/playwright/phase2-closeout/`，属于本地可重建验收产物，不纳入 Git。

## 收尾文案事实清单

| 事实 ID | 用户事实 | 主承载位置 | 生命周期 | 下一步 |
| --- | --- | --- | --- | --- |
| F01 | 所选范围没有已接收事件 | 窗口空状态 | 首批事件前/范围改变前 | 调整范围或等待上报 |
| F02 | Processor 没有提供统计 | 图表区域状态；统计值为 — | 统计可用前 | 查看样本/导出 |
| F03 | 覆盖率不是业务正确率 | KPI 提示 | 查看时 | 按显式规则/样本核对质量 |
| F04 | 评分延迟含排队，不是业务耗时 | 延迟 KPI 提示 | 查看时 | 对照待处理量 |
| F05 | 暂停仍持续接收 | 计划状态条 | 已暂停期间 | 恢复评分 |
| F06 | 当前详情是固定快照，已有新修订 | Drawer 局部状态 | 新修订出现且未查看前 | 查看最新或导出当前快照 |
| F07 | 原因按指标计数；策略单位数可重叠 | Drawer 的“指标原因分布”“涉及”标签 | 详情打开期间 | 核对统计/样本 |
| F08 | 当前详情读取/导出未完成 | Drawer 局部安全错误 | 恢复/关闭前 | 局部重试 |

## 本轮图像与代码复核

| Before | After | Why |
| --- | --- | --- |
| 页面用 scored / eligible 计算覆盖率，缺延迟显示 0 | 直接读取 Processor coverage；缺值显示 — | 自定义/关闭处理器时不制造默认统计，缺失不等于零 |
| p95 读取业务 latency | 读取接收至评分计算完成的时间事实 | 区分评测积压和被测请求耗时 |
| 每次 SSE 都销毁并创建 ECharts | 实例生命周期与 option 更新分离，监听并清理 reduced-motion；reduce 模式下画布更新稳定，卸载后实例数从 4 归零 | 保留实例、减少重建，并以浏览器运行时证据覆盖初始化、更新和清理 |
| 详情读取可能被旧请求覆盖，错误没有就地重试 | 请求版本保护、局部重试、新修订单独提示 | 不丢失快照上下文或悄悄切换导出对象 |
| 事件时间 pending 被称为积压历史 | Processor 用接收/完成时钟生成 backlog series | 区分事件时间窗口分布与真实处理过程的积压 |
| 200% 等效视口仍使用固定桌面侧栏，标题逐字换行且页面宽度 883px | 820px 以内切换顶部导航与紧凑布局，页面宽度与 768px 视口一致 | 主操作不被遮挡，浏览器放大用户无需横向寻找页面内容 |
| 旧普通 Chrome 扩展链路曾阻断本机地址 | 当前普通 Chrome 新标签页已成功打开真实页面并完成 200%→100% 缩放；确定性流程仍由独立 Chromium 承担 | 重新验证当前环境，不再把旧阻断当作当前结论 |
| 空计划在 SSE 先返回时持续显示“正在读取窗口” | SSE snapshot 同步结束 loading，空计划显示稳定空状态 | 避免把已完成的空结果误报为仍在加载 |
| 原记录称原型和实现使用同一数据 | 明确原型为静态方向稿，只比较层级、密度、控件与布局；实际 fixture 单独留存截图 | 不用不可复现的“1:1”声明掩盖数值和结构差异 |
